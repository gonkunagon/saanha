# SAANHA

China sourcing / supplier payment / shipping business website (Thai market). Next.js 16 App Router, TypeScript, Tailwind v4.

- All pages live under `src/app/[locale]/` (`th` default, `en`). `src/proxy.ts` redirects locale-less URLs.
- UI text goes in `src/i18n/dictionaries/{th,en}.json` — keep both files' keys identical (`th.json` is the type source).
- Knowledge base = Markdown in `content/kb/<locale>/<slug>.md` with frontmatter (title, description, category, order). Same slug in both locales. Categories are defined in `src/lib/kb.ts`.
- Rates and contact info are config, not code: `src/config/rates.ts` (shipping rates per product type × method), `src/config/site.ts`. Current values are placeholders.
- No standalone CNY exchange service (dropped Nov 2026) — only paying Chinese suppliers on the customer's behalf. Never show an exchange rate on the public site. The one exception is the back-office quotation (`/admin/quote/[id]`): CNY orders convert to THB, and the quote is valid only for that day. Rate (`getQuoteRate` in `src/lib/settings.ts`, stored in `app_settings`) = market rate fetched from open.er-api.com (fallback Frankfurter/ECB; cached 1 h) + the shop's markup (`cny_markup`), unless staff set a manual rate for today (`cny_rate`, ignored after the Bangkok day ends).
- Back office at `/admin` (Thai only, outside `[locale]`; excluded in `src/proxy.ts`). Every page and server action calls `requireUser()` from `src/lib/auth.ts` (HMAC-signed cookie, `AUTH_SECRET`). Staff accounts in `users`; first one via `npm run user:create`.
- DB: Drizzle + Postgres on Supabase (`src/db`, driver `postgres`, `DATABASE_URL` = Transaction pooler URL (port 6543; Session mode caps at 15 clients and ran out once Vercel was added) in `.env.local` and in Vercel; the direct `db.<ref>.supabase.co` host is IPv6-only and unreachable from this PC). Every table has RLS enabled with no policies, so the public Data API sees nothing; the app connects as the owner. Schema change → `npm run db:generate` then `db:migrate`. `local.db` + `drizzle-sqlite/` are the pre-Nov 2026 SQLite data/migrations, kept only as a backup (copied once by `npm run db:copy-from-sqlite`). Dev and the live site share the same Supabase DB.
- Domain: order → many order_items; each item sits in at most one container, so an order can span containers. Transit stages live on the container (updating it moves every item); China-warehouse receipt and delivery live on items (partial delivery). Stage logic is in `src/lib/stages.ts`; order status = slowest item. `provider` + `external_id` on orders/containers are for a future partner-API sync.
- Customers (`customers` table, `/admin/customers`, `src/lib/customers.ts`): orders link via nullable `customer_id` but still snapshot name/phone/LINE on the order (tracking uses the order's phone). Phone is unique per customer, compared by digits only. New orders must pick a saved customer (`CustomerPicker`: search + quick add); the order's name/phone/LINE are copied from the customer and re-synced when the customer is edited. Older unlinked orders (JJ imports) keep their own name/phone until linked.
- JJ Cargo integration (`src/lib/jjcargo.ts`, action `orders/jj-actions.ts`): logs into the partner's internal API with `JJ_CARGO_*` env (cookie session, re-login on 401), `GET /api/packing?tracking=` (partial match → we filter exact). Each JJ packing row = 1 box; the "ดึง" button in `PackageFields` fills package rows. Never hard-code or commit the partner credentials.
- JJ full sync (`src/lib/jjsync.ts`, button `orders/SyncJjButton.tsx`, cron `/api/cron/jj-sync`): idempotent via `import_key` on orders (`jj:c<cust>:o<jjOrder>:d<bkkDay>`), items (`…:t<tracking>:s<shipment>`), packages (`jj:<packingId>`). Container dates only fill empty fields. `JJ_CARGO_CUSTOMER_CODES` (comma list, case-insensitive) limits both sync and lookup to those JJ customers. Imported orders may have an empty phone; `getTrackingView` rejects phones with <4 digits.
- Customer tracking (`/[locale]/track` → `src/app/api/track/route.ts` → `getTrackingView` in `src/lib/orders.ts`) needs order code + phone last 4, rate-limited per IP; groups items by container.
- Quote form posts to `src/app/api/quote/route.ts`, which pushes a LINE Messaging API message (env: `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_TARGET_ID`; logs only if unset).
- Commands: `npm run dev`, `npm run build`, `npm run typecheck`.
- Hosting (for now): saanha.com + www run from this Windows PC. Cloudflare tunnel `saanha` (config `%USERPROFILE%\.cloudflared\config.yml`) → `next start` on port 3000, both started at login by Task Scheduler tasks "SAANHA Web" / "SAANHA Tunnel" (`scripts/run-web.cmd`, `scripts/run-tunnel.cmd`, launched via `conhost --headless` — PowerShell and wscript hang when started by Task Scheduler on this machine). Logs in `logs/` (git-ignored). After code changes, run `scripts/redeploy.ps1` (stop → build → start). Dev preview uses port 3001 so it doesn't clash with the live server.
- Moving the server to another PC: `scripts/pack-server.cmd` on the old PC (stops + disables its tasks, copies project, `.env.local`, tunnel key to `Desktop/SAANHA-move`), then `SANHA/scripts/setup-server.cmd` on the new one (needs Node.js + cloudflared; `npm ci`, build, rewrites the tunnel key path, registers the tasks). Never run both PCs at once — they share the tunnel. `scripts/resume-server.cmd` undoes the pack.
