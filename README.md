# SANHA — เว็บไซต์ชิปปิ้งจีนครบวงจร

เว็บไซต์ของบริการนำเข้าสินค้าจากจีนแบบ One Stop Service: รับหาสินค้า, สั่งซื้อแทน, ฝากจ่าย / แลกหยวน, ขนส่งทางรถและทางเรือ จนถึงมือลูกค้า

## เริ่มต้น

ต้องติดตั้ง [Node.js](https://nodejs.org) เวอร์ชัน 20 ขึ้นไปก่อน

```bash
npm install
npm run db:migrate
npm run dev
```

เปิด http://localhost:3000 (ระบบจะพาไปที่ `/th` อัตโนมัติ)

## โครงสร้าง

```
content/kb/<th|en>/*.md     บทความคู่มือ / FAQ (Markdown)
src/config/site.ts          ข้อมูลติดต่อบริษัท
src/config/rates.ts         เรทค่าขนส่ง แยกตามประเภทสินค้า (เรทหยวนไม่แสดงบนเว็บ ให้สอบถามทาง LINE)
src/i18n/dictionaries/      ข้อความบนเว็บ ภาษาไทย / อังกฤษ
src/app/[locale]/           หน้าเว็บทั้งหมด
src/app/api/quote/          รับข้อมูลจากฟอร์มขอใบเสนอราคา
src/app/admin/              ระบบหลังบ้าน (ออเดอร์ ตู้ พนักงาน)
src/db/schema.ts            โครงสร้างฐานข้อมูล
drizzle/                    ไฟล์ migration ของฐานข้อมูล
```

## ตั้งค่าการแจ้งเตือนฟอร์มเข้า LINE

ฟอร์มขอใบเสนอราคาจะส่งข้อความเข้า LINE ของทีมงานผ่าน LINE Messaging API (ถ้ายังไม่ตั้งค่า ระบบจะแค่บันทึกไว้ใน log ของเซิร์ฟเวอร์)

1. สร้าง LINE Official Account และเปิดใช้ Messaging API ที่ [LINE Developers Console](https://developers.line.biz/console/)
2. ในแท็บ Messaging API กด Issue **Channel access token (long-lived)**
3. หา ID ของผู้รับ:
   - ส่งให้ตัวเอง: ใช้ **Your user ID** ในแท็บ Basic settings (ขึ้นต้นด้วย `U`)
   - ส่งเข้ากลุ่มทีม: เชิญ OA เข้ากลุ่ม แล้วดู Group ID (ขึ้นต้นด้วย `C`) จาก webhook event
4. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_TARGET_ID`
5. รีสตาร์ท `npm run dev`

> Push message นับรวมในโควต้าข้อความรายเดือนของ LINE OA ตามแพ็กเกจที่ใช้

## ระบบหลังบ้าน (/admin)

พนักงานล็อกอินที่ `/admin` เพื่อจัดการออเดอร์และตู้ ลูกค้าเห็นสถานะที่ `/th/track` ทันทีที่อัปเดต

### ตั้งค่าครั้งแรก

```bash
npm run db:migrate
npm run user:create -- <username> "<ชื่อที่แสดง>"
```

คำสั่งที่สองสร้างบัญชีพนักงานคนแรกและแสดงรหัสผ่านครั้งเดียว พนักงานคนต่อไปเพิ่มได้จากหน้า **พนักงาน** ในหลังบ้าน

### โครงสร้างข้อมูล

- **ออเดอร์** : ข้อมูลลูกค้า วิธีขนส่ง บริษัทขนส่งที่รับงานต่อ และ **External ID** (เลขอ้างอิงของบริษัทนั้น) ระบบออกเลขออเดอร์ให้อัตโนมัติ เช่น `SH2611-0001`
- **รายการสินค้า** : 1 ออเดอร์มีหลายรายการ แต่ละรายการอยู่ได้ 1 ตู้ → **1 ออเดอร์อยู่หลายตู้ได้** ถ้าสินค้าชิ้นเดียวกันแบ่งไปหลายตู้ ให้แยกเป็นหลายรายการ
- **ตู้** : 4 สถานะ (ปิดตู้/โหลดที่จีน → ออกจากจีน → ถึงด่าน/ตรวจปล่อย → ถึงโกดังไทย) **อัปเดตตู้แล้วทุกออเดอร์ในตู้เปลี่ยนตามเอง**

### ขั้นตอนทำงานประจำวัน

1. **ออเดอร์ → สร้างออเดอร์** แล้วเพิ่มรายการสินค้า
2. สินค้าถึงโกดังจีน → ในหน้าออเดอร์กด **ถึงโกดังจีน → บันทึกทั้งหมด** (หรือใส่วันที่ทีละรายการ)
3. **ตู้ → สร้างตู้** แล้วติ๊กเลือกสินค้าที่รอเข้าตู้ → **เพิ่มเข้าตู้**
4. อัปเดตสถานะตู้แต่ละขั้นในหน้าตู้
5. ตู้ถึงโกดังไทยแล้ว → ในหน้าออเดอร์กด **ส่งออกให้ลูกค้า** (ใส่เลขพัสดุไทย) และ **จัดส่งสำเร็จ** ส่งบางส่วนได้ถ้าตู้แรกถึงก่อน
6. ส่งเลขออเดอร์ให้ลูกค้าทาง LINE ลูกค้าเช็คเองที่หน้า **ติดตามพัสดุ** ด้วยเลขออเดอร์ + เบอร์โทร 4 ตัวท้าย

### ฐานข้อมูลบนเว็บจริง

ตอน dev ข้อมูลอยู่ในไฟล์ `local.db` (ไม่ถูก commit) บนเว็บจริงต้องใช้ฐานข้อมูลออนไลน์ เช่น [Turso](https://turso.tech) ตั้งค่า `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `AUTH_SECRET` แล้วรัน `npm run db:migrate`

แก้โครงสร้างข้อมูลใน `src/db/schema.ts` แล้วรัน `npm run db:generate` ตามด้วย `npm run db:migrate`

### อนาคต: ดึงสถานะจากบริษัทขนส่ง

ออเดอร์และตู้มีช่อง `provider` + `external_id` ไว้แล้ว ขั้นต่อไปคือเชื่อม API ของบริษัทขนส่ง ให้ดึงสถานะมาอัปเดตตู้อัตโนมัติแทนการกรอกเอง
