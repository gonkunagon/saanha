# SANHA — เว็บไซต์ชิปปิ้งจีนครบวงจร

เว็บไซต์ของบริการนำเข้าสินค้าจากจีนแบบ One Stop Service: รับหาสินค้า, สั่งซื้อแทน, ฝากจ่าย / แลกหยวน, ขนส่งทางรถและทางเรือ จนถึงมือลูกค้า

## เริ่มต้น

ต้องติดตั้ง [Node.js](https://nodejs.org) เวอร์ชัน 20 ขึ้นไปก่อน

```bash
npm install
npm run db:migrate
npm run dev
```

เปิด http://localhost:3000 (ระบบจะพาไปที่ `/th` อัตโนมัติ)

content/kb/<th|en>/*.md     บทความคู่มือ / FAQ (Markdown)

## ตั้งค่าการแจ้งเตือนฟอร์มเข้า LINE

ฟอร์มขอใบเสนอราคาจะส่งข้อความเข้า LINE ของทีมงานผ่าน LINE Messaging API (ถ้ายังไม่ตั้งค่า ระบบจะแค่บันทึกไว้ใน log ของเซิร์ฟเวอร์)

1. สร้าง LINE Official Account และเปิดใช้ Messaging API ที่ [LINE Developers Console](https://developers.line.biz/console/)
2. ในแท็บ Messaging API กด Issue **Channel access token (long-lived)**
3. หา ID ของผู้รับ:
   - ส่งให้ตัวเอง: ใช้ **Your user ID** ในแท็บ Basic settings (ขึ้นต้นด้วย `U`)
   - ส่งเข้ากลุ่มทีม: เชิญ OA เข้ากลุ่ม แล้วดู Group ID (ขึ้นต้นด้วย `C`) จาก webhook event
4. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_TARGET_ID`
5. รีสตาร์ท `npm run dev`

> Push message นับรวมในโควต้าข้อความรายเดือนของ LINE OA ตามแพ็กเกจที่ใช้

## ระบบหลังบ้าน (/admin)

พนักงานล็อกอินที่ `/admin` เพื่อจัดการออเดอร์และตู้ ลูกค้าเห็นสถานะที่ `/th/track` ทันทีที่อัปเดต

### ตั้งค่าครั้งแรก

```bash
npm run db:migrate
npm run user:create -- <username> "<ชื่อที่แสดง>"
```

คำสั่งที่สองสร้างบัญชีพนักงานคนแรกและแสดงรหัสผ่านครั้งเดียว พนักงานคนต่อไปเพิ่มได้จากหน้า **พนักงาน** ในหลังบ้าน

### โครงสร้างข้อมูล

- **ออเดอร์** : ข้อมูลลูกค้า วิธีขนส่ง บริษัทขนส่งที่รับงานต่อ และ **External ID** (เลขอ้างอิงของบริษัทนั้น) ระบบออกเลขออเดอร์ให้อัตโนมัติ เช่น `SH2611-0001`
- **รายการสินค้า** : 1 ออเดอร์มีหลายรายการ แต่ละรายการอยู่ได้ 1 ตู้ → **1 ออเดอร์อยู่หลายตู้ได้** ถ้าสินค้าชิ้นเดียวกันแบ่งไปหลายตู้ ให้แยกเป็นหลายรายการ
- **ตู้** : 4 สถานะ (ปิดตู้/โหลดที่จีน → ออกจากจีน → ถึงด่าน/ตรวจปล่อย → ถึงโกดังไทย) **อัปเดตตู้แล้วทุกออเดอร์ในตู้เปลี่ยนตามเอง**

### ขั้นตอนทำงานประจำวัน

ทุกอย่างทำได้ในหน้าออเดอร์หน้าเดียว:

1. **ออเดอร์ → สร้างออเดอร์** กรอกข้อมูลลูกค้าและรายการสินค้าในฟอร์มเดียว
2. ในหน้าออเดอร์ ติ๊กเลือกรายการ → เลือก **สถานะใหม่** → กด **บันทึกสถานะ**
   - ขั้น "ปิดตู้" ขึ้นไป ให้พิมพ์ **เลขตู้** (มีให้เลือก หรือพิมพ์เลขใหม่ = สร้างตู้ใหม่ให้อัตโนมัติ)
   - ข้ามขั้นได้ ขั้นก่อนหน้าที่ยังว่างจะใส่วันที่ให้เอง
   - ขั้นของตู้ (ปิดตู้ → ถึงโกดังไทย) บันทึกที่ตู้ ออเดอร์อื่นในตู้เดียวกันจะเปลี่ยนตามด้วย (มีข้อความเตือน)
   - เลือกเฉพาะบางรายการได้ = ส่งของบางส่วน
3. ส่งเลขออเดอร์ให้ลูกค้าทาง LINE ลูกค้าเช็คเองที่หน้า **ติดตามพัสดุ** ด้วยเลขออเดอร์ + เบอร์โทร 4 ตัวท้าย

หน้า **ตู้** ยังใช้ได้ สำหรับดูภาพรวมของตู้ หรืออัปเดตสถานะตู้เดียวที่มีหลายออเดอร์ในครั้งเดียว

### ฐานข้อมูลบนเว็บจริง

ตอน dev ข้อมูลอยู่ในไฟล์ `local.db` (ไม่ถูก commit) บนเว็บจริงต้องใช้ฐานข้อมูลออนไลน์ เช่น [Turso](https://turso.tech) ตั้งค่า `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `AUTH_SECRET` แล้วรัน `npm run db:migrate`

แก้โครงสร้างข้อมูลใน `src/db/schema.ts` แล้วรัน `npm run db:generate` ตามด้วย `npm run db:migrate`

### ดึงข้อมูลพัสดุจาก JJ Cargo

ในแถวพัสดุ พิมพ์เลขพัสดุจีนแล้วกดปุ่ม **ดึง** ระบบจะไปค้นในระบบ JJ Cargo แล้วเติมให้ทุกกล่องของเลขนั้น (1 กล่อง = 1 แถว: น้ำหนัก กว้าง × ยาว × สูง และคิว) พร้อมแสดงรอบขนส่งและวันออกจากจีน — ตรวจสอบแล้วค่อยกดบันทึก

ตั้งค่าครั้งเดียวใน `.env.local` แล้วรีสตาร์ท `npm run dev`:

```
JJ_CARGO_URL=https://<โดเมนระบบ JJ Cargo>
JJ_CARGO_USERNAME=<ชื่อผู้ใช้ของบริษัทเราในระบบ JJ>
JJ_CARGO_PASSWORD=<รหัสผ่าน>
```

#### ซิงค์ทั้งหมดจาก JJ Cargo เข้าหลังบ้าน

หน้า **ออเดอร์** กดปุ่ม **↻ ซิงค์จาก JJ Cargo** ระบบจะดึงพัสดุทั้งหมดจาก JJ แล้วสร้าง/อัปเดตให้อัตโนมัติ

| JJ Cargo | SANHA |
|---|---|
| ลูกค้าเดียวกัน + ออเดอร์ JJ เดียวกัน + รับเข้าโกดังจีนวันเดียวกัน | 1 ออเดอร์ (ออกเลขให้อัตโนมัติ) |
| 1 เลขแทรคในรอบขนส่งเดียวกัน | 1 รายการ (ออเดอร์เดียวมีได้หลายเลขแทรค และกระจายหลายตู้ได้) |
| 1 PackingList (กระสอบ/กล่อง) | 1 พัสดุ: น้ำหนัก ขนาด คิว |
| รอบขนส่ง | ตู้ชื่อเดียวกัน พร้อมวันขึ้นตู้ / ออกจากจีน / ถึงไทย (วันถึงไทยที่ยังไม่ถึงไม่ถูกบันทึก) |

- กดซ้ำได้ ไม่สร้างซ้ำ: พัสดุใหม่ถูกเพิ่ม พัสดุเดิมอัปเดตน้ำหนัก/ขนาด และย้ายเข้าตู้เมื่อ JJ จัดรอบขนส่ง
- วันที่ของตู้ระบบเติมเฉพาะช่องที่ยังว่าง ถ้าพนักงานแก้เองแล้วจะไม่ถูกทับ
- ลูกค้าใน JJ ที่ไม่มีเบอร์โทร: ออเดอร์จะขึ้นป้าย "ยังไม่มีเบอร์" ลูกค้าเช็คสถานะเองไม่ได้จนกว่าพนักงานจะใส่เบอร์
- ซิงค์ตามเวลา: ตั้ง `CRON_SECRET` แล้วให้ cron เรียก `GET /api/cron/jj-sync` พร้อม header `Authorization: Bearer <CRON_SECRET>` (เช่น Vercel Cron ทุก 1 ชั่วโมง)

- ใช้ API ภายในของเว็บ JJ Cargo (`/api/login`, `/api/packing`, `/api/r/shipments`, `/api/customers`) ไม่ใช่ API ทางการ ถ้า JJ เปลี่ยนระบบอาจต้องแก้ `src/lib/jjcargo.ts` และ `src/lib/jjsync.ts`
- แนะนำให้ขอบัญชีแบบ **อ่านอย่างเดียว** จาก JJ สำหรับใช้เชื่อมระบบ แทนบัญชี admin

### อนาคต: ดึงสถานะจากบริษัทขนส่ง

ออเดอร์และตู้มีช่อง `provider` + `external_id` ไว้แล้ว ขั้นต่อไปคือเชื่อม API ของบริษัทขนส่ง ให้ดึงสถานะมาอัปเดตตู้อัตโนมัติแทนการกรอกเอง
